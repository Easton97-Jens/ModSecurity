## 1. Was dieses Repository baut

Das Hauptziel für die Bibliothek ist `libmodsecurity.la`. Seine Quelldateien werden in `src/Makefile.am` zusammengestellt, darunter Transaktionen, Regelauswertung, Parser, Aktionen, Operatoren, Variablen, Body-Parser und Logging. Der Automake-Einstieg auf oberster Ebene durchläuft `others`, `src`, `doc`, `tools` sowie, abhängig von der Konfiguration, `examples` und `test`. Quellen: [Bibliotheksziel](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/Makefile.am#L11-L14), [Quelldateien](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/Makefile.am#L255-L288), [Unterverzeichnisse](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/Makefile.am#L2-L17).

HTTP-Daten gelangen über die `Transaction`-API oder ihre `msc_*`-Wrapper in die Bibliothek. Upstream beschreibt einen Webserver-Connector als eigenständiges Projekt; die hier enthaltenen Beispiele zeigen Bibliotheksaufrufe. Quellen: [Transaction-API](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/headers/modsecurity/transaction.h), [C-Wrapper](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/transaction.cc#L1832-L1904), [Upstream-Erklärung zur Trennung der Connectors](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/README.md).

## 8. Originalquellen, erzeugte Dateien und Submodule unterscheiden

**Parser:** `seclang-parser.yy` und `seclang-scanner.ll` sind die maßgeblichen Spracheingaben. Die `.cc`-/`.hh`-Dateien des erzeugten Parsers sind ebenfalls versioniert. `src/Makefile.am` kennzeichnet sie ausdrücklich als bereits erzeugten Parser, und `src/parser/Makefile.am` führt Generatoreingaben und erzeugte Dateien auf. Eine Grammatikänderung erfordert deshalb einen bewussten Abgleich von Eingabe und erzeugtem Ergebnis. Quellen: [Dateiliste](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/Makefile.am#L17-L28), [Generator-Build](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/parser/Makefile.am).

**Autotools:** `configure.ac` und `Makefile.am` sind versionierte Eingaben; `build.sh` erzeugt unter anderem `src/headers.mk` und startet die Generatoren. `configure`, `Makefile`, `Makefile.in`, `src/config.h`, Objektdateien und `.libs` stehen in `.gitignore`. Quellen: [Build-Vorbereitung](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/build.sh#L6-L32), [Ignorierliste](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/.gitignore#L1-L35).

**HTML-Entities:** Der Kommentar in `tools/gen-html-entities.py` erklärt die Erzeugung der Tabelle benannter Entities; die `HtmlEntityDecode`-Implementierung enthält den entsprechenden erzeugten Tabellenabschnitt. ## 9. Verlässliche Orientierung für eine neue Aufgabe

Die folgenden Befehle sind Lesehilfen dieser Dokumentation. Führe sie im Stammverzeichnis des Repositorys aus; sie verändern keine Quelldateien:

```sh
git status --short
git rev-parse HEAD
git ls-tree --name-only HEAD
rg --files src headers examples test tools build
rg -n 'class Transaction|processRequestBody|msc_process_request_body' headers src
rg -n 'RuleWithOperator::evaluate|RulesSet::evaluate' src
rg -n 'SecRuleEngine|SecRequestBodyAccess' modsecurity.conf-recommended src/parser
```

Gib für Aufgaben mit ignorierten oder versteckten Dateien den Pfad ausdrücklich an, zum Beispiel `rg --files .github .oss-scanner`. Beurteile eine Änderung ausgehend vom konkreten Symptom und den zugehörigen Dateien. Diese Übersicht dient der Orientierung; tatsächlicher Code und ein nachvollziehbarer Testlauf bleiben die Belege für Verhalten und Korrektheit.
